# Existing lead flows (MPF, RMW, CT)

Inspected 2026-11-09, read-only. Nothing in the existing projects was changed. This document is the basis for the adapters in `backend/src/integrations/`.

## Summary

| | MPF (MyPropertyFact) | RMW (Ritz Media World) | CT (Contenaissance) |
|---|---|---|---|
| Lead store | MySQL `enquiries` (Spring Boot, `mpf-backend`) | MySQL `enquiries` (Next.js, `rmw-backend`) plus Mongo `EnquiryTracker` copy | MySQL `leads` (Next.js, `contenaissance`) |
| Create endpoint | `POST /api/v1/enquiry/post` (and `/post-app`) | `POST /api/system-settings/contact-enquiry` | `POST /api/enquiry` |
| Lead ID | INT auto-increment | INT auto-increment | INT auto-increment |
| CRM external ID | `MPF-<id>` | `RMW-<id>` | `CT-<id>` |
| UTM capture | Yes: first-touch UTM, gclid, fbclid, msclkid, referrer, landing/exit page in `metadata_json` | None | None |
| Form identifier | `page_name`, `project_link`; `enquiry_from` is always WEBSITE/APP | `etype` (ContactUs, career, HomePageDownload, NavbarConsulting, NewspaperAdEnquiry, contact) | `type` (contact/footer) + free-text `source` |
| Statuses | Free text: New, Shared, Test, Pending, Rejected, Duplicate, Irrelevant (null = New) | None | Pending, Contacted, Qualified, Converted, Lost |
| Outbound hook today | **Already built**: `CrmIntegrationService.pushEnquiry()` (async, after save) | Telegram only (awaited) | Telegram only |

## MPF

Flow: site forms (popup, project page, contact, chatbot, blog) → `POST /api/v1/enquiry/post` → `EnquiryService.addUpdate()` → spam validator → `enquiries` save → `notifyEnquiryIntegrationsAsync()` → Telegram + `CrmIntegrationService.pushEnquiry()`.

**Outbound CRM webhook (already in `mpf-backend`)**
- Enabled when both `CRM_WEBHOOK_URL` and `MPF_CRM_WEBHOOK_KEY` are set on the MPF backend.
- `POST <CRM_WEBHOOK_URL>`, header `x-mpf-crm-key: <key>`, JSON body:
  `externalId, name, email, phone, message, enquiryFrom, pageName, projectLink, status, whatsapp?, createdAt (ISO, no timezone = IST), metadata`.
- `metadata` = `{ utm:{utm_source, utm_medium, utm_campaign, utm_term, utm_content, gclid, fbclid, msclkid, referrer, landing_page, exit_page}, device, geo, journey, session, analytics, property? }`.
- It also fires on updates (`id > 0`), so the CRM upserts on `externalId`.
- RestTemplate has no timeout configured; exceptions are swallowed.

**Pull fallback**: `GET /api/v1/enquiry/crm-export` with the same `x-mpf-crm-key` header returns all enquiries.

**Gaps**: Eldeco landing pages post to a separate 4QT CRM route (`app/api/crm-lead`) and never reach `enquiries`. The chatbot also writes to a Next-side `form_leads` table.

**MPF changes needed: none.** Set `CRM_WEBHOOK_URL=https://<crm-api>/api/integrations/mpf/enquiry` and `MPF_CRM_WEBHOOK_KEY=<key generated by the CRM>` in the MPF backend environment.

## RMW

Flow: new-rmw / rmw-frontend / rmw-backend forms → (new-rmw: `/api/contact` OTP check, forwards) → `POST https://ritzmediaworld.com/api/system-settings/contact-enquiry` (rmw-backend) → `INSERT INTO enquiries (etype, name, email, mobile, message, category, resume)` → Mongo `EnquiryTracker` (IP/geo) → Telegram.

- `enquiries` columns: `id, etype, name, email, mobile, message, category, resume, send_date`.
- new-rmw packs "Reason for Inquiry", "Country" and "How did you hear about us" into `message`.
- No UTM, referrer or landing page is captured anywhere.
- The new-rmw "Start a project / audit" form (`/api/audit`) only logs to the console; those leads are lost today.
- The admin enquiry list/delete endpoints do not check the JWT (existing security gap, outside CRM scope).

**RMW change needed (small, additive):** after the INSERT in `rmw-backend/src/app/api/system-settings/contact-enquiry/route.ts`, take `insertId` and send a non-blocking POST to the CRM. See `docs/INTEGRATION_GUIDE.md`. To get attribution, new-rmw would also need to capture UTM/referrer/landing page on the client and pass them through `/api/contact`. The CRM adapter already accepts those fields.

## CT

Flow: contact page / sidebar forms → OTP via `/api/otp-proxy` → `/api/enquiry-proxy` → production `POST /api/enquiry` → `INSERT INTO leads` → Telegram. The floating popup posts to Google Apps Script, then directly to `/api/enquiry`.

- `leads` columns: `id, type (contact|footer), full_name, email, phone, service, message, source, status, notes, created_at, updated_at`.
- `source` is free text: `new-website-contact`, `<page url>#lead-popup`, `contact-page`, `footer`.
- Country is embedded in `message` ("Country: X").
- No UTM capture.

**CT change needed (small, additive):** after the INSERT in `contenaissance/app/api/enquiry/route.ts`, capture `insertId` and send a non-blocking POST to the CRM. This must be deployed on production `www.contenaissance.com`, because the proxies forward there.

## SMS OTP gateway (shared, from CT `lib/otp.ts`)

`GET SMS_API_URL?apikey=&senderid=&number=&message=`, with India numbers as 10 digits (no 91). The response is plain text; only the HTTP status is checked. The message must match the DLT-approved template exactly. The CRM's `otpService.js` uses this exact contract.
